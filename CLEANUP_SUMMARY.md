## 🎨 Architecture Summary

```
User Input (iOS) 
    ↓
POST /api/plans/generate
    ↓
AIPlanGenerationService
    ├─→ ConstraintParser (natural language)
    ├─→ ExerciseSelector (DB query + weights)
    ├─→ CardioSelector (goal-based defaults)
    └─→ OpenAIService (GPT-4o with structured prompts)
        ↓
    Validated Plan (JSON)
        ↓
    Return to iOS
```

**Key Principles:**
1. Backend-owned logic (iOS just collects data)
2. Database strictness (only DB exercises allowed)
3. Safety guardrails (age/experience rules)
4. Natural language constraints (OpenAI interprets)
5. Single API call (stateless, no conversation)

## 📝 Notes

- All tests use **real database** (Supabase PostgreSQL) in **READ-ONLY** mode
- OpenAI API key and database URL are in `.env`
- Constraint system lets OpenAI interpret user intent within guardrails
- Age/experience adaptations ensure safe exercise selection
- Weight recommendations work even for exercises without DB standards
